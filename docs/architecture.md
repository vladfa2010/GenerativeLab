# Архитектура сервиса

## Принцип

Три узла с чётким разделением труда. Аудио никогда не покидает устройство модератора —
на сервер уходит только текст. Это и дешевле, и сильный аргумент приватности против
облачных транскрайберов (Fireflies, Otter и т.п.).

## Узлы

### 1. VPS — сердце сервиса
- Веб-приложение: доска, заметки модератора, экран входа
- Backend API + WebSocket-сервер (реальное время)
- PostgreSQL: встречи, тезисы, голоса, комментарии, история
- Redis: pub/sub между процессами, presence
- AI-модуль: черновики тезисов и кластеризация тем из потока текста (этап 2+)

### 2. Локальный агент модератора (этап 2, автотранскрипт)
- Захват системного звука звонка (macOS: BlackHole/Loopback; Windows: WASAPI loopback; Linux: PulseAudio/PipeWire)
- faster-whisper локально + VAD (Silero) для нарезки на реплики
- Лёгкая кластеризация спикеров (resemblyzer), имена подключаются вручную один раз
- Стримит только текстовые сегменты на VPS по WSS

### 3. Участники — чистый браузер
- Заход по ссылке, самоидентификация (имя, отдел, роль)
- Ничего не устанавливают

## Поток данных (одна встреча)

1. Модератор создаёт встречу → ссылка для команды + ключ сессии для агента
2. (Этап 2) Агент слушает звук, стримит реплики: `{спикер, текст, время}`
3. Сервер раздаёт реплики на доску; AI предлагает черновики тезисов
4. Модератор публикует тезис → мгновенная доставка всем участникам
5. Голоса и комментарии — события по WebSocket, сервер пересчитывает Σ и статусы
6. После встречи в БД остаётся артефакт: карта тем, решения, расхождения

## События протокола (направление)

- `transcript.segment` — агент → сервер → окно модератора (этап 2)
- `thesis.created / thesis.updated` — модератор → всем
- `vote.cast` — участник → сервер → пересчёт Σ → всем
- `comment.added` — участник → всем
- `presence.joined / left` — сервер → всем

## Почему транскрибация на устройстве, а не на VPS

- Приватность: «звук не покидает ваш ноут» — готовый маркетинговый тезис
- Экономика: без аудиопотоков VPS 2–4 CPU / 4 ГБ тянет десятки параллельных встреч;
  серверный Whisper потребовал бы GPU
- Отказоустойчивость: обрыв агента не роняет доску, реплики подтянутся после переподключения

## Этап 1 — ручной режим (текущий)

Без звука. Модератор вводит тезисы руками из своих заметок.
Стек минимальный: Node или FastAPI + PostgreSQL + WebSocket + фронт из мокапа.

## Безопасность

- TLS везде; комната — по неугадываемому ключу (UUID)
- Аудио не хранится нигде; транскрипты — с политикой retention
- Никаких секретов в репозитории
