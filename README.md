# Cifra — Generative Lab

> Интерактивная веб-платформа для создания генеративного арта. 21 алгоритм, микрофон, акселерометр, спектр «правило — хаос», 15-урочный курс. Один HTML-файл, без сборки, открывается двойным кликом.

**Текущая версия:** v8 (21 алгоритм + Code view + Daily piece + Walk + курс + всё предыдущее)
**Размер кода:** ~1.2 MB в одном файле (p5.js заинлайнен)
**Зависимости:** p5.js v1.9.4 (инлайн в `<script>`), ноль сборки, ноль сервера, работает офлайн
**Лицензия:** внутренний проект, передаётся на проверку

## 1. Концепция

### Что это

**Cifra** — это веб-«мастерская», в которой пользователь создаёт генеративный арт через диалог с 21 алгоритмом. Не рисует руками, а **пишет правила** (через ползунки), **выбирает зерно** (seed) и **наблюдает**, что получается.

### Ключевая философия

Вдохновлено двумя принципами:

1. **Vera Molnár (1924–2023)** — «бабушка компьютерного искусства». С 1959 года она использовала «воображаемую машину» (machine imaginaire) для систематического перебора вариантов. Её правило: *«Я сравниваю результаты, пока не найду тот, который нужен. **Последнее слово всегда за мной, а не за программой**».* Подкручивание (tinkering) — самый важный жест в практике.

2. **Casey Reas** (со-создатель Processing): *«Process as artwork»* — сам процесс поиска, перебора, сравнения и есть художественное высказывание, а не только финальный кадр.

Из этого вытекает архитектура Cifra: пользователь не получает готовую работу, он участвует в её рождении.

### Аудитория

- **Художники и дизайнеры**, которые хотят понять, что такое генеративный арт, без необходимости сразу писать код
- **Студенты и преподаватели** — встроенный 15-урочный курс с теорией и заданиями
- **Любопытствующие** — кому интересно «что будет, если покричать в микрофон» и увидеть, как это превращается в арт
- **Разработчики**, которые хотят использовать платформу как playground / исследовательскую среду

### Что отличает от конкурентов

- **Не «ещё один AI-генератор»** — Cifra не использует ML-модели, вся генерация детерминированная, на чистом JS
- **Воспроизводимость** — каждый результат можно сохранить как seed + параметры и поделиться URL'ом; получатель увидит **точно то же**
- **Семья работ** — один seed в разных алгоритмах даёт «родственников» — концепция, которой нет у большинства платформ
- **Образовательный слой** — встроенный курс, code view, документация в самом продукте
- **Без сборки, без бэка** — открывается в браузере, всё локально

- Файл большой (~156 KB), но это кешируется браузером после первой загрузки

## 4. Алгоритмы — 21 штука

Все алгоритмы описаны единообразно как объект в реестре `ALGORITHMS`:

```js
ALGORITHMS = {
  flow_field: {
    label: 'Flow Field',           // UI-имя
    short: 'Краткое описание',     // 1 строка для UI
    sensorReinit: false,           // параметры захватываются в init() или нет
    sensors: { bass: 'X', ... },   // привязка датчиков к параметрам
    about: { intro, param, seed }, // для секции "О проекте"
    params: [...],                 // массив параметров с метаданными
    init(p, state, ctx) { ... },   // инициализация state алгоритма
    draw(p, state, ctx) { ... },   // отрисовка кадра
  }
}
```

### Категории алгоритмов

#### 4.1 Геометрия и тайлинг

| ID | Название | Описание |
|---|---|---|
| `truchet` | **Truchet Tiles** | Квадратная сетка, в каждой ячейке — две дуги в противоположных углах. Два варианта ориентации на ячейку, выбор случайный. Классический мотив Себастьяна Трюше (1704). |
| `phyllotaxis` | **Phyllotaxis** | Спираль Фибоначчи. Точки расставляются по спирали: каждая следующая — под углом к предыдущей. Классический «золотой угол» — 137.508°. |
| `maze` | **Maze** | Лабиринт через recursive backtracker. Алгоритм копает коридор, натыкается на тупик, возвращается и пробует другое направление. |
| `voronoi` | **Voronoi** | N случайных точек разбивают плоскость на ячейки: для каждого пикселя ищется ближайшая точка. |
| `lsystem` | **L-systems** | Lindenmayer systems. Аксиома + правила переписывания → строка команд → черепаха (turtle graphics) её исполняет → дерево/папоротник. Пресеты: tree, bush, fern, weed. |
| `penrose` | **Penrose** | Апериодическая мозаика. Robinson triangle subdivision. Мозаика из тонких и толстых ромбов, никогда не повторяется периодически. |

#### 4.2 Кривые и аттракторы

| ID | Название | Описание |
|---|---|---|
| `spirograph` | **Spirograph** | Гипотрохоида. Маленький круг радиуса r катится внутри большого R. Точка на расстоянии d от центра малого круга рисует классическую спирографическую кривую. |
| `lissajous` | **Lissajous** | Кривые Лиссажу. X = sin(a·t + δ), Y = sin(b·t). Соотношение частот определяет форму. |
| `lorenz` | **Lorenz** | Аттрактор Лоренца. Система трёх дифференциальных уравнений (1963). Знаменитая «бабочка», странный аттрактор, чувствительность к начальным условиям. |
| `clifford` | **Clifford** | Аттрактор Клиффорда-Пиковера. Двухмерное отображение: xₙ₊₁ = sin(a·yₙ) + c·cos(a·xₙ). Четыре параметра (a, b, c, d) дают радикально разные узоры. |

#### 4.3 Органика и emergence

| ID | Название | Описание |
|---|---|---|
| `game_of_life` | **Game of Life** | Клеточный автомат Конвея (1970). Четыре правила: живая с 2-3 соседями выживает, мёртвая с 3 — оживает. Emergence: из простых правил вырастают глайдеры, осцилляторы, целые колонии. |
| `reaction_diffusion` | **Reaction-Diffusion** | Модель Грея-Скотта. Два реагента диффундируют с разной скоростью. Узоры зависят от параметров feed/kill. Классические пресеты: coral, mitosis, spots, waves. |
| `boids` | **Boids** | Flocking по Рейнольдсу (1987). Три правила: разделение, выравнивание, сплочённость. Получаются стаи птиц/рыб. |
| `dla` | **DLA** | Diffusion-Limited Aggregation. Частицы блуждают случайно, прилипают к кластеру. Получается фрактальный ветвистый кристалл. |

#### 4.4 Фракталы

| ID | Название | Описание |
|---|---|---|
| `mandelbrot` | **Mandelbrot** | Классический фрактал. Для каждой точки комплексной плоскости итерируется z = z² + c. Точки, не уходящие в бесконечность, — внутри множества. |
| `julia` | **Julia** | Множество Жюлиа. Та же итерация z = z² + c, но c фиксировано. Получаются «бабочки», зависящие от c. |
| `barnsley` | **Barnsley Fern** | Папоротник Барнсли. IFS из четырёх аффинных преобразований с разными вероятностями. |
| `pythagoras` | **Pythagoras Tree** | Классическое фрактальное дерево. Квадрат, на нём прямоугольный треугольник, на каждом катете — новый квадрат, рекурсия. |

#### 4.5 Поля и волны

| ID | Название | Описание |
|---|---|---|
| `flow_field` | **Flow Field** | Поток частиц по шумовому полю Перлина. Каждая частица движется по углу, заданному шумом. |
| `curl_noise` | **Curl Noise** | Бездивергентное движение. Тот же шум, но вместо градиента берётся его curl (поворот на 90°). Получаются более «жидкие», текучие траектории. |
| `wave_interference` | **Wave Interference** | Несколько «источников» излучают синусоидальные волны. В каждой точке холста складываются амплитуды — концентрические узоры интерференции. |

### Реализация ключевых алгоритмов

Ниже — детальный разбор самых важных и показательных алгоритмов.

#### 4.5.1 Flow Field

**Концепция.** Каждая частица движется по полю скоростей, заданному шумом Перлина.

**Параметры:**
- `complexity` (0.001-0.020) — масштаб шума. Маленькие значения = крупные вихри, большие = мелкая рябь
- `density` (100-3000) — количество частиц
- `mutation` (0-1) — степень случайного блуждания поверх шумового поля
- `palette` — цветовая схема

**Реализация init():**
- Создаётся массив `ctx.particles` заданного размера
- Каждая частица получает случайные координаты,寿命, цвет
- `ctx.z` — счётчик времени для анимации (смещение по третьему измерению шума)

**Реализация draw():**
1. Накладывается полупрозрачный чёрный прямоугольник (создаёт «хвосты» у частиц)
2. Для каждой частицы:
   - Вычисляется угол из шумовой функции: `angle = noise(x, y, z) * 4π`
   - Позиция обновляется: `x += cos(angle) * 1.2; y += sin(angle) * 1.2`
   - С вероятностью `mutation * 4%` добавляется случайное смещение
   - Рисуется круг радиуса 1.5 пикселя с полупрозрачностью
3. Если частица вышла за границы или умерла (life истекло) — пересоздаётся

**Сенсорные привязки:**
- bass → complexity
- mid → mutation
- treble → density
- tiltY → complexity

#### 4.5.2 Game of Life

**Концепция.** Сетка клеток (Uint8Array для производительности). На каждом кадре все клетки одновременно обновляются по правилам Конвея.

**Параметры:**
- `cellSize` (4-24px) — размер одной клетки
- `density` (0.05-0.60) — начальная плотность заполнения
- `speed` (0-20) — сколько поколений симулировать за кадр
- `trail` (0-0.6) — шлейф (затухание предыдущих поколений)

**Реализация init():**
- Вычисляется `cols × rows` ячеек
- Создаётся `Uint8Array(ctx.cols * ctx.rows)` — сетка живых/мёртвых клеток
- Создаётся второй буфер `Uint8Array` — для двойной буферизации (старая сетка → новая сетка, без перезаписи)
- Заполнение: для каждой ячейки — `rng() < density ? 1 : 0`

**Реализация stepLife() — отдельная функция:**
- Для каждой клетки считается количество живых соседей в окрестности Мура (8 клеток)
- Применяются правила:
  - Живая с 2 или 3 соседями → выживает
  - Мёртвая с ровно 3 → оживает
  - Иначе → умирает
- Граничные условия — тор (клетки за краем «оборачиваются» с другой стороны)

**Реализация draw():**
- `speed` раз вызывается `stepLife()` для симуляции N поколений за кадр
- Если `trail > 0` — накладывается полупрозрачный чёрный прямоугольник
- Иначе — полная очистка фона
- Каждая живая клетка рисуется цветом из палитры (сдвиг по позиции + номер поколения)

**Почему Uint8Array вместо обычного массива:**
- В 5-10 раз быстрее на больших сетках (плотные данные в непрерывной памяти)
- Меньше памяти (1 байт на клетку вместо ~30)

#### 4.5.3 Reaction-Diffusion (Gray-Scott)

**Концепция.** Модель Тьюринга для морфогенеза. Два реагента (A и B) диффундируют с разной скоростью и взаимодействуют по формулам:

```
∂A/∂t = DA · ∇²A − A·B² + feed · (1 − A)
∂B/∂t = DB · ∇²B + A·B² − (kill + feed) · B
```

**Параметры:**
- `feed` (0.01-0.10) — скорость подачи реагента A
- `kill` (0.04-0.07) — скорость разрушения реагента B
- `steps` (1-25) — количество итераций за кадр

**Реализация:**
- Сетка 100×100 = 10000 клеток
- `Float32Array` для A и B (для дробных значений концентраций)
- 9-точечный лапласиан: `∇²f(i,j) = 0.2 · (N+S+E+W) + 0.05 · (NE+NW+SE+SW) − f(i,j)`
- Граничные условия — тор
- Начальные условия: A=1 везде, B=0 везде, кроме 15 случайных круглых «семян», где B=1
- Каждый кадр: 6 итераций симуляции (по умолчанию)
- Рендер: для каждой клетки — `fillRect` цветом из палитры, по значению B

**Производительность:**
- ~10000 клеток × 9 лапласиан × 6 итераций = 540k операций/кадр
- При 60fps = 32M операций/сек — на грани возможностей JS
- Поэтому cellSize фиксирован (100×100), пользователь не может увеличить разрешение

#### 4.5.4 Mandelbrot

**Концепция.** Для каждого пикселя комплексной плоскости итерируется `z = z² + c`, начиная с z₀ = 0. Если |z| остаётся ограниченным (≤ 2) — точка внутри множества (чёрная). Если убегает — точка снаружи (цвет по скорости побега).

**Параметры:**
- `centerX` (-2.5 — 1) — действительная часть центра фрактала
- `centerY` (-1.5 — 1.5) — мнимая часть центра
- `zoom` (0.5-5) — масштаб
- `iterations` (30-150) — глубина итераций

**Реализация:**
- Попиксельный рендер через `p.drawingContext.fillRect` (в 10× быстрее, чем `p.rect`)
- Шаг 4 пикселя (даёт пиксельный стиль, но экономит время)
- Максимум 70 итераций по умолчанию (баланс скорости и детализации)
- При zoom > 1 появляется артефакт «сетки» — это сознательный выбор (как у первых рендеров на мейнфреймах)

**Сенсорные привязки:**
- bass → zoom
- mid → centerX
- treble → centerY
(Позволяет «летать» сквозь фрактал, напевая или наклоняя телефон)

#### 4.5.5 Lorenz

**Концепция.** Система дифференциальных уравнений:

```
dx/dt = σ(y − x)
dy/dt = x(ρ − z) − y
dz/dt = xy − βz
```

**Параметры:**
- `sigma` (1-30) — обычно 10
- `rho` (1-60) — обычно 28
- `beta` (0.5-8) — обычно 2.667
- `iterations` (1000-15000) — длина траектории
- `scale` (4-25) — масштаб отрисовки

**Реализация init():**
- Метод Эйлера с dt=0.01
- Стартовая точка — случайная в пределах [-10, 10] × [-10, 10] × [10, 40]
- N итераций, точки сохраняются в `ctx.points = [{x, y, z}, ...]`
- Вычисляются min/max для автоматического масштабирования

**Реализация draw():**
- Проекция 3D → 2D: используются только x и y
- Автоматическое центрирование и масштабирование
- Линия рисуется по точкам, цвет по индексу (сдвиг по палитре)
- Тонкая линия (strokeWeight 1) — даёт характерный «трассирующий» вид

#### 4.5.6 L-systems

**Концепция.** Аксиома + правила переписывания = строка команд. Черепаха (turtle graphics) исполняет.

**Команды:**
- `F` — движение вперёд с рисованием
- `+` — поворот направо на угол
- `−` — поворот налево на угол
- `[` — сохранить позицию
- `]` — восстановить позицию

**Пресеты:**
- `tree`: F → F[+F]F[-F]F
- `bush`: F → FF+[+F-F-F]-[-F+F+F]
- `fern`: X → F[+X]F[-X]+X, F → FF
- `weed`: F → F[+FF][-FF]F[-F][+F]F

**Реализация:**
- Итеративное применение правил N раз
- Черепаха с состоянием: x, y, направление, стек сохранённых состояний
- Толщина линии уменьшается с глубиной рекурсии
- Скругление линий (ROUND) для эстетики

## 5. Сенсоры: микрофон и наклон

### Архитектура сенсорной подсистемы

```
[Микрофон]            [Акселерометр]
     │                      │
     ▼                      ▼
AnalyserNode         DeviceMotionEvent
(FFT 2048)            (с усреднением)
     │                      │
     ▼                      ▼
state.micBass       state.tiltX
state.micMid        state.tiltY
state.micTreble
     │                      │
     └──────────┬───────────┘
                ▼
      applySensorModulation()
                │
                ▼
   state.params[paramId] обновляется
                │
                ▼
   updateParamVisual() — UI обновляется
```

### 5.1 Микрофон (Web Audio API)

**Получение доступа:**
```js
micStream = await navigator.mediaDevices.getUserMedia({
  audio: { echoCancellation: false, noiseSuppression: false, autoGainControl: false }
});
```

**Важно:** все три «улучшайзера» отключены, чтобы получить «сырой» сигнал. Без этого полосы бы работали искажённо.

**FFT и частотные полосы:**
- `fftSize = 2048` → `frequencyBinCount = 1024` (половина от fftSize)
- Sample rate: обычно 44100 или 48000 Hz
- Ширина одного бина: `sampleRate / fftSize` ≈ 23 Hz при 48kHz

**Разделение на полосы:**
- **bass** (20-250 Hz) — бины 1-10
- **mid** (250-2000 Hz) — бины 10-90
- **treble** (2000+ Hz) — бины 90-1024

**Нормализация:**
- `state.micBass = avg(bins 1..10) / 255 × 3` (×3 эмпирически)
- `state.micMid = avg(bins 10..90) / 255 × 2`
- `state.micTreble = avg(bins 90..1024) / 255 × 4`
- `Math.min(1, ...)` — обрезка до [0, 1]
- Smoothing: `analyser.smoothingTimeConstant = 0.6` (плавность на 60%)

**Метрика «общей громкости» (state.micLevel):**
- `(bass + mid + treble) / 3` — для отображения в старой метре

### 5.2 Акселерометр (DeviceMotion API)

**Подписка:**
```js
window.addEventListener('devicemotion', onMotion);
```

**Обработка:**
- Берём `e.accelerationIncludingGravity.x` и `.y` (с гравитацией, а не чистое ускорение — это даёт «наклон», а не «движение»)
- Сглаживание: последние 12 событий усредняются (это убирает дрожание рук)
- Нормализация: `±10 m/s² → ±1` (10 м/с² — примерно 1g, нормальная гравитация)
- `Math.max(-1, Math.min(1, ...))` — обрезка

**iOS особенность:** Safari требует явного разрешения через `DeviceMotionEvent.requestPermission()`. Реализовано в `enableTilt()`.

### 5.3 Sensor Mappings (привязки)

Каждый алгоритм в реестре `ALGORITHMS` имеет поле `sensors`:

```js
sensors: {
  bass: 'complexity',     // bass → параметр complexity
  mid: 'mutation',        // mid → параметр mutation
  treble: 'density',      // treble → параметр density
  tiltX: 'angle',         // наклон X → параметр angle
  tiltY: 'scale'          // наклон Y → параметр scale
}
```

Можно указать любую комбинацию. Если датчик выключен — его привязки неактивны.

### 5.4 Применение сенсоров к параметрам (applySensorModulation)

Вызывается в `p.draw()` **каждый кадр**:

```js
function applySensorModulation() {
  let modified = false;
  if (state.sensors.mic) {
    const bands = { bass: state.micBass, mid: state.micMid, treble: state.micTreble };
    for (const band of ['bass', 'mid', 'treble']) {
      const pid = algo.sensors[band];
      if (!pid) continue;
      const param = algo.params.find(x => x.id === pid);
      const range = param.max - param.min;
      state.params[pid] = param.min + bands[band] * range;  // 0..1 → min..max
      updateParamVisual(pid, param);  // обновить UI
      modified = true;
    }
  }
  // ... аналогично для tilt
  return modified;
}
```

**Если алгоритм sensorReinit: true** (init захватывает параметры), то после `applySensorModulation()` мы вызываем `algo.init()` заново — чтобы новые значения попали в контекст.

**Если sensorReinit: false** (параметры читаются в draw каждый кадр), просто обновляем state.params, и draw использует новые значения.

## 6. Спектр «правило — хаос»

### Концепция

Глобальный ползунок `state.spectrum ∈ [0, 1]`, контролирующий баланс между детерминизмом и случайностью. Это философский компас Cifra — каждая работа может быть размещена на спектре.

- **0% (Pure Rule)** — всё детерминировано, как обычно
- **100% (Pure Chaos)** — параметры дрожат, рисунок постоянно меняется

### Реализация

```js
function applySpectrum() {
  if (state.spectrum < 0.01) return false;  // off
  const algo = ALGORITHMS[state.algorithm];

  // Для one-shot алгоритмов (init захватывает параметры) —
  // частая reinit с новыми случайными значениями
  if (!algo.continuous) {
    if (Math.random() < state.spectrum * 0.4) {
      algo.init(p, state, ctx);
      return true;
    }
  }

  // Для всех алгоритмов — джиттер одного случайного параметра
  const numericParams = algo.params.filter(x => x.type !== 'select');
  const param = numericParams[Math.floor(Math.random() * numericParams.length)];
  const range = param.max - param.min;
  const jitter = (Math.random() - 0.5) * range * state.spectrum * 0.6;
  state.params[param.id] = clamp(current + jitter, min, max);
  return true;
}
```

### Визуализация

Ползунок с градиентом: синий (`#4a90e2`) → серый (`#9b9ba0`) → оранжевый (`#ff6b3d`). Слева надпись `PURE RULE`, справа `PURE CHAOS`. Текущее значение отображается в процентах.

Значение также включается в Shareable URL (параметр `?spectrum=0.50`).

## 7. Контент-фичи: галерея, семья, code view, share

### 7.1 Галерея

**Хранение:** `localStorage['cifra-gallery-v6']` — массив объектов:

```js
{
  seed: 'AB12CD',          // 6-символьный seed
  algorithm: 'flow_field', // ID алгоритма
  config: { ... },        // снимок state.params
  spectrum: 0,            // значение спектра
  ts: 1696704000000,      // timestamp
  thumb: 'data:image/...' // dataURL превью
}
```

**Лимит:** максимум 24 работы (при добавлении 25-й самая старая удаляется).

**Отрисовка:** CSS Grid, автоматическое количество колонок (min 220px). Каждая карточка:
- Алгоритм-чип в верхнем левом углу
- Изображение-превью
- При наведении: meta-информация (дата + seed) + кнопки «Семья» и «×»

### 7.2 Семья (Relatives)

**Концепция.** Один seed в разных алгоритмах даёт «родственников» — серию работ, объединённых общей числовой сущностью. Это уникальная для Cifra концепция, основанная на наблюдении, что одно число (seed) может «звучать» совершенно по-разному в разных алгоритмах.

**Реализация:**
- Кнопка «↗ Семья» на каждой карточке в галерее
- Открывает модалку с сеткой 21 алгоритм
- Текущий алгоритм помечен оранжевой рамкой
- Карточки алгоритмов генерируются как placeholder-градиент с лейблом (для полноценного рендера 21 инстанса p5.js потребовалось бы 21 окно — слишком тяжело)
- Клик по карточке → переключает на тот алгоритм + тот же seed + те же параметры (если были сохранены)

**Ограничение:** в текущей реализации карточки в модалке — placeholder, а не настоящий рендер. Для настоящего рендера нужна либо Web Worker-система, либо постепенная генерация. Сейчас UX компромиссный: визуальный hint, что существуют родственники, + клик-переключение.

### 7.3 Code View

**Концепция.** Показать пользователю **реальный код**, который генерирует работу. Это образовательный элемент, отличающий Cifra от «ещё одного генератора картинок».

**Реализация:**
- Drawer внизу холста (свернут по умолчанию)
- Код берётся через `algo.init.toString()` и `algo.draw.toString()` — **реальный**, не очищенный
- Простая подсветка синтаксиса: ключевые слова оранжевые, числа зелёные, строки синие, комментарии серые
- Кнопка `copy` — копирует в буфер
- Код обновляется при смене алгоритма или seed

**Свернуть/развернуть:**
- Свёрнут: 40px высота, показывает только заголовок
- Развёрнут: до 60% высоты canvas-wrap, показывает код в `<pre>`

**Ограничение:** drawer накрывает нижнюю часть холста. Когда развёрнут — пользователь видит верхние 40% работы. Это сознательный компромисс ради образовательной ценности.

### 7.4 Shareable URL

**Формат:** `?algo=flow_field&seed=AB12CD&complexity=0.006&density=900&spectrum=0.30`

**Генерация (`buildShareUrl()`):**
- Берёт текущее состояние
- Сериализует в URLSearchParams
- Возвращает полный URL

**Парсинг (`applyStateFromUrl()`):**
- Вызывается на init
- Если `algo` валиден — устанавливает state, иначе возвращает false
- Валидация каждого параметра (min/max для числовых, options для select)
- Валидация spectrum (0-1)

**UI:** кнопка `↗ Поделиться` копирует URL в буфер.

**Безопасность:** все параметры проверяются на допустимые диапазоны, чтобы URL с инъецированными значениями не сломал алгоритм.

## 8. Генеративные сессии: time-lapse, walk, daily

### 8.1 Time-lapse (3 секунды)

**Реализация:** использует `MediaRecorder` + `canvas.captureStream(30)`.

```js
const stream = canvas.captureStream(30);
const recorder = new MediaRecorder(stream, { mimeType: 'video/webm' });
recorder.ondataavailable = e => chunks.push(e.data);
recorder.onstop = () => {
  const blob = new Blob(chunks, { type: 'video/webm' });
  // скачивание через <a download>
};
recorder.start();
setTimeout(() => recorder.stop(), 3000);
```

**UI:** кнопка `⏺ Записать 3 сек`. На холсте красный `● REC` индикатор с пульсацией. Кнопка меняется на `⏹ Остановить`.

**Совместимость:** работает в Chrome и Firefox. Safari может не поддерживать `captureStream` для `<canvas>`.

### 8.2 Walk (30 секунд)

**Концепция.** Автопилот: 30 секунд плавно меняет случайный параметр каждые 500ms, делает 60 скриншотов. Результат — «прохождение» через пространство параметров алгоритма.

**Реализация:**
- `setInterval` каждые 500ms:
  - Выбирается случайный числовой параметр
  - Ему присваивается новое случайное значение в диапазоне
  - `canvas.toDataURL('image/jpeg', 0.6)` сжимает кадр
- Параллельно запускается `MediaRecorder` для записи видео
- Через 30 секунд (или при ручной остановке):
  - Останавливается recorder
  - Последний кадр захватывается
  - Открывается модалка с 60 миниатюрами

**UI Walk модалки:**
- Заголовок «Walk завершён», счётчик кадров
- Сетка миниатюр (флипбук)
- Кнопка `⤓ Скачать видео (.webm)`
- Кнопка `🔁 Повторить` — закрывает модалку и сразу запускает новый Walk

**Когда использовать:** на алгоритмах с несколькими параметрами (Reaction-Diffusion, Lorenz, Phyllotaxis) Walk покажет «траекторию» через параметрическое пространство — интересно визуально.

**Ограничение:** кадры хранятся в памяти (60 × ~50KB = 3MB). Не сохраняются автоматически — если закрыть модалку, пропадают.

### 8.3 Daily piece (ежедневная работа)

**Концепция.** Каждый день в 00:00 UTC генерится seed на основе даты. Все, кто заходят в этот день, видят одну и ту же работу. За год — 365 уникальных работ, по одной на день.

**Реализация:**
- `getDailySeed()`: `Date.toUTCString()` → `YYYY-MM-DD` → хеш → `YYYY-MM-DD-XXXX`
- `getDailyDateLabel()`: `7 октября 2026` (русский формат)
- Кнопка `📅 [дата] [взять]` в панели управления

**Воспроизводимость:** в любой день, в любое время при нажатии «взять» загружается один и тот же seed. Это даёт «общий опыт» — все пользователи, зашедшие в один день, видят одну работу.

**Расширение (в roadmap):** галерея «Daily» — сетка за 7/30/365 дней, навигация по датам.

## 13. Поток данных в p5.draw

Это центральный цикл приложения, выполняется ~60 раз в секунду:

```
p.draw() каждый кадр:
│
├── 1. updateAudioBands()
│      если state.sensors.mic:
│        micAnalyser.getByteFrequencyData(buffer)
│        вычислить state.micBass, micMid, micTreble
│
├── 2. applySensorModulation()
│      если mic включён:
│        для каждой привязки bass/mid/treble:
│          state.params[pid] = param.min + bandValue * range
│          updateParamVisual()  // обновить UI слайдера
│      если tilt включён:
│        аналогично для tiltX/tiltY
│      return modified
│
├── 3. applySpectrum()
│      если state.spectrum > 0:
│        если !continuous && random() < spectrum * 0.4:
│          algo.init()  // пересоздать
│        иначе:
│          jitter одного случайного параметра
│
├── 4. если (sensor || spectrum модифицировали) && algo.sensorReinit:
│        algo.init()  // пересоздать контекст с новыми параметрами
│
├── 5. algo.draw(p, state, ctx)
│      - отрисовка текущего кадра алгоритма
│      - модифицирует ctx (particles, grid, points, etc.)
│
├── 6. обновить визуализацию датчиков (CSS)
│      - micMeter widths
│      - tiltDot transform
└── конец кадра
```

**Два типа алгоритмов:**

**Continuous** (sensorReinit: false): параметры читаются в `draw()` каждый кадр. Примеры: flow_field, boids, game_of_life, reaction_diffusion.

**One-shot** (sensorReinit: true): параметры захватываются в `init()`, draw просто рендерит захваченное. Примеры: lorenz, mandelbrot, julia, truchet, phyllotaxis, clifford, barnsley, pythagoras, lsystem, penrose, lissajous, wave_interference, voronoi, dla.

## 14. Ограничения и компромиссы

### 14.1 Семья (Relatives)

**Текущее состояние:** карточки алгоритмов в модалке — placeholder-градиент с лейблом, а не настоящий рендер.

**Почему:** 21 одновременный p5-инстанс = 21 canvas с 60fps = тяжело для браузера, особенно на слабых устройствах.

**Возможные решения:**
- Web Worker для каждого алгоритма (OffscreenCanvas) — настоящий offscreen-рендер
- Постепенная генерация: показать N карточек сразу, остальные — по клику «Загрузить ещё»
- Использовать статичные превью (генерируются в момент сохранения, кешируются)

### 14.2 Reaction-Diffusion — фиксированное разрешение

Сетка 100×100 захардкожена. Пользователь не может увеличить разрешение (производительность). Это явный trade-off: детализация vs скорость.

**Возможные решения:** динамическое разрешение в зависимости от производительности (FPS-мониторинг).

### 14.3 Mandelbrot/Julia — пиксельный стиль

Шаг 4 пикселя даёт артефакт «сетки» при zoom > 1. Это сознательный выбор в пользу производительности (попиксельный рендер 600×600 = 360k пикселей, на каждом до 70 итераций = 25M операций, это уже на грани).

**Возможные решения:** Web Worker + OffscreenCanvas, или рендер в WebGL через шейдер.

### 14.4 MediaRecorder — не везде

Работает в Chrome и Firefox. Safari может не поддерживать `captureStream` для canvas.

**Возможные решения:** fallback на запись кадров в массив + создание анимированного GIF через стороннюю библиотеку (gif.js ~30KB).

### 14.5 Один файл = большой размер

156 KB. Не критично, но если хочется ускорить загрузку — можно разделить на модули с lazy loading.

**Возможные решения:** Vite-bundle с code splitting.

### 14.6 Спектр-jitter для one-shot алгоритмов

Спектр применяет джиттер к параметрам, но для one-shot алгоритмов это менее заметно (раз всё равно reinit). Для них лучше работает режим «полная reinit со случайными параметрами» — реализован через `if (!algo.continuous)`.

### 14.7 Code view накрывает часть холста

Когда drawer развёрнут, видно только верхние ~40% холста. Это trade-off между «видеть работу целиком» и «видеть код, который её генерирует».

**Возможные решения:** split-view (холст слева, код справа) с регулируемым разделителем.

### 14.8 L-systems — палеты

Поддерживаются только 4 пресета (tree, bush, fern, weed). Пользователь не может задать свои правила.

**Возможные решения:** UI для ввода собственных правил.

- **Web Worker для Relatives** — настоящий предрендер всех 21 алгоритмов

### Идеи для будущих версий
- **«Cifra как дневник»** — галерея автоматически привязывается к дате, через год — 365 работ-воспоминаний
- **Сезонные коллекции** — раз в месяц «drop» из 100 работ, ограниченное время
- **Курс-расширение** — добавить уроки по AI (GenP5, Style Transfer), 3D (Three.js), шейдерам (Shadertoy)

## 16. Глоссарий

**Seed (зерно)** — числовое или строковое значение, из которого детерминированно вычисляется последовательность «случайных» решений. Один seed → одна работа. Vera Molnár, Casey Reas, Art Blocks — все используют seed как первичный артефакт.

**Pseudorandom (псевдослучайность)** — последовательность, которая выглядит случайной, но генерируется детерминированным алгоритмом (PRNG) из seed'а. В Cifra используется `mulberry32`.

**Noise (шум)** — гладкая функция, которая даёт «естественные» вариации. В отличие от random, близкие точки дают близкие значения. Самый известный — Perlin noise (Кен Перлин, 1983).

**Emergence (эмерджентность)** — глобальное поведение, возникающее из локальных правил. Клетки Game of Life не знают, что формируют глайдер, но он появляется. Стаи Boids не имеют лидера, но координируются.

**Strange attractor (странный аттрактор)** — фрактальная траектория в фазовом пространстве динамической системы. Траектория остаётся ограниченной, но никогда не повторяется. Классический пример — аттрактор Лоренца (бабочка).

**Fractal (фрактал)** — фигура, у которой часть похожа на целое на любом масштабе. Самоподобие. Ключевое свойство — дробная размерность.

**Cellular automaton (клеточный автомат)** — дискретная модель, определённая на сетке. Каждая ячейка имеет состояние, обновляемое по локальным правилам. Game of Life — самый знаменитый.

**IFS (Iterated Function System)** — система сжимающих отображений, генерирующая фрактал при итеративном применении. Barnsley fern — классический пример.

**Turing patterns (паттерны Тьюринга)** — пространственные узоры, возникающие из реакции-диффузии двух реагентов. Модель Грея-Скотта — частный случай. Объясняет полосы зебры, пятна леопарда.

**Tinkering (подкручивание)** — термин Molnár. Постепенное изменение параметров, сравнение результатов, выбор лучшего. Самый важный жест в практике генеративного арта.

**Process as artwork** — формулировка Casey Reas. Сам процесс поиска работы — и есть художественное высказывание.

**Vera Molnár (1924-2023)** — «бабушка компьютерного искусства». С 1959 года использовала «machine imaginaire», затем Fortran + плоттер. Цитата: «Последнее слово всегда за мной, а не за программой».

**Casey Reas** — со-создатель Processing (с Ben Fry, 2001). Профессор UCLA Design Media Arts. Концепция «process as artwork».

**Curl noise** — бездивергентное векторное поле, получаемое из curl (поворота градиента) шумовой функции. Используется для симуляции жидкостей.

**Lindenmayer system (L-system)** — система переписывания строк, моделирующая рост растений. Аксиома + правила → строка команд → turtle graphics → дерево.
